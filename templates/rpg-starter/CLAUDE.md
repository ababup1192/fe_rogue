# このゲームの開発方針

エンジン本体の CLAUDE.md・`/quality-assurance` skill の要約版。新しいゲームはこの方針で始める。

## テスト方針

- テストするのは「ゲームのルール・進行・収支」と「JSON とプログラムの橋渡し」だけ。
- モーション・表示タイミング・座標の写経はテストしない — 演出は golden（bake 比較）と目視の仕事。
  ただしクリック当たりの有無はルールなので残す。
- 期待値は数値リテラルでなく Doc（JSON 既定値）から導く。バランス調整でテストが壊れないように。
- JSON 橋渡しは 1 Doc につき最大3本（壊れたら既定値 / 1 フィールド上書き / rows 長の追随）。
- initialState の写経など情報量ゼロのテストは書かない。

## JSON（Doc）化の判断基準

- **JSON 化する**: 繰り返し調整する数値（テンポ・閾値・収支・確率）、個数が増減するデータ
  （rows: 配置・敵・アイテム）、色テーマ、文言。判断軸は「保存即反映で調整できると嬉しいか」。
- **JSON 化しない**: 描画アルゴリズム・演出の形（モーションの振り付け）、導出できる値、
  一度決めたら触らない構造。ロジックを JSON に書き始めたら設計の匂い。
- 作法: 1 種類 = 1 Doc、fail-open（欠け・壊れは既定値）、既定値はコード側、watchFile で保存即反映。

## 絵の開発ループ

- 決定的な場面を headless bake で `debug/` に焼き（golden の外）、目視で批評 → 修正 → 再焼成を回す。
- 機械的リファクタ（分割・Doc 化）は「前後の PNG バイト一致」で見た目不変を証明する。
- リグレッション防護は golden（`gallery/` vs `golden/` のバイト比較）。

## Bake / golden の作り方

- `Bake.all()` のような entrypoint を用意し、Bakery.renderPng で決定的な場面
  （t を固定し、乱数や実時間に依存しない world）を `gallery/` に焼く。
- 焼いた PNG を `golden/` にコピーして基準にし、make のターゲットでバイト比較する。
- 調整中の画は `debug/` 行きの別 entrypoint（例: `Bake.prologue`）に分け、golden を汚さない。
