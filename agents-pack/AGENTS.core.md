# エージェント共通指針（エンジン公式・全ゲーム共有）

このファイルはエンジンの agents-pack から配られる共通部。ゲーム固有の方針は
同じフォルダの `AGENTS.local.md` に書く。

## Doc 規約（ゲームデータ JSON）

- **1 種類 = 1 Doc + 1 スキーマ**（`<名前>.<種類>.json` と `<種類>.schema.json`）。
  外側の形は全 Doc 共通: `version` を持ち、`note` フィールド歓迎。
- **読み込みは fail-open**。書き損じや欠けは既定値へ倒す。既定値はコード側に持つ。
- **watchFile で保存即反映**。調整のたびに再起動しない。
- **データは Doc・振る舞いはコード**。繰り返し調整する数値（テンポ・閾値・収支・確率）、
  個数が増減するデータ（rows）、色テーマ、文言は Doc へ。描画アルゴリズム・演出の形・
  導出できる値・ルールはコードのまま。ロジックを JSON に書き始めたら設計の匂い。
- **プレイヤーの目に入る文言は必ず Doc に置く（既定値はコード側）**。
  コード直書きの表示文字列は違反 — Studio から変えられない。
- **ドット絵の `legend` の意味色キーは色票に実体を置く**。Studio が名前を実色に解けるのは
  `*.theme.json` のトップレベル・sprite Doc の `paletteFile` が指す色票・直下の `palette` の
  3 つだけ。つや・影のような派生色をコードで導いたままにすると Studio は仮色で塗り、
  編集画面と実機で配色が食い違う。導くなら色票 JSON を生成して `paletteFile` で指す。

## atelier/ 規約（採用前の候補置き場）

- `atelier/` は **採用前の候補**を置く場所。中身は `assets/` と同じ Doc 形式。
- `assets/` のパスは**スロット**（Doc の `entityId` で互換を確認する）。
- 採用は **swap**: 候補の中身をスロットへ移す(候補ファイルは消える)。それまでの中身は
  `atelier/archive/<base>.vN.<kind>.json` に積まれる(何も捨てない。戻すのもここから)。
- **AI が素材を作るときは `assets/` に直接書かず、必ず `atelier/` に書く。**

## make の入口

- `make run` / `make debug`（watchFile・F8 有効）/ `make check`（型検査・一番速い確認）
- `make test` / `make bake`（決定的な絵を焼く）/ `make bench`（gallery/ vs golden/ のバイト比較）
- `make golden`（いまの gallery を基準にする）
- `debug/` のコンタクトシート系ターゲット（例: `make gallery-prologue` の all.png、
  `make gallery-sounds` の sounds.png / music.png）で**目視・目聴**して批評する。

## テスト方針（要約）

- テストするのは「ゲームの**ルール・進行・収支**」と「JSON とプログラムの橋渡し」だけ。
  モーション・表示タイミング・座標の写経はテストしない（演出は golden と目視の仕事）。
  ただしクリック当たりの有無はルールなので残す。
- **期待値は Doc（JSON 既定値）から導く**。数値リテラルを貼らない。
- 橋渡しテストは **1 Doc につき最大3本**（壊れた JSON→既定値 / 1 フィールド上書き /
  rows 長の追随）。initialState の写経など情報量ゼロのテストは書かない。

## エンジン API 優先(車輪の再発明禁止)

- 実装の前に engine リポの `docs/module-index.md`(「やりたいこと → モジュール」の逆引き)を引く。
  メニュー・スクロール・文字折り・当たり判定・タイムライン・**マップ地形(rows を塗るだけの
  デュアルグリッド = Terrain / TerrainDoc、タイルセット PNG = MapResource)**など、
  **エンジンにある物を自前で書かない**。
- 各モジュールの詳しい使い方は `engine_world/src/<名前>.flix` 冒頭の doc コメントと、
  templates/ のスターターにある実使用例が正。
- 迷ったら「低い API で書けたか」ではなく「一番高い API で書けたか」を疑う。
  自前実装が残っていたら、それはレビュー(critique)で指摘される対象。

## 初学者の足場（生成コードに必須）

このエンジンの成果物は「初学者が仕組みを読み取れる」ことを謳う。以下は飾りでなく
**生成・拡張の完了条件**。新しいゲームにも、既存への追加にも常に満たす。

- **読む順序**: README に「まずどのファイルをどの順で読むと全体像が掴めるか」を一節置く。
  **遊ぶ → 読む順（エントリ→状態→描画）→ JSON をいじる** の 3 段。専用ファイルは増やさない。
- **ゲームループの明示**: エントリ（Main 相当）か状態モジュール（World 相当）の冒頭 doc に、
  **毎フレーム 入力→状態更新→描画 のどれがどこか**を数行で書く（addSystem / withView の
  どの行が何か）。場面（フェーズ）遷移があれば 1 行の遷移図（`title → play → clear`）。
- **JSON（Doc）の学びやすさ**: 各 Doc の `note` に「いじると何が変わるか」、調整ノブ（数値）に
  効果の一言。可能なら最小例。schema の `label` / `description` を埋める（空の schema は違反）。
- **黒箱に触れたら engine 解説へ誘導**: 高抽象 API（`Terrain.fromRows` 等）を呼ぶ箇所に
  **「これは何をするか」一言 + 解説の在り処（engine の `docs/module-index.md`）**への言及を残す。
  呼ぶだけで意味の見えない一行を放置しない。

## 絵の下限（生成コードに必須）

画面を作る前に **`.claude/skills/visual-dict` を引く**（頼まれてからではなく、View を書く前に
毎回）。engine の `docs/module-index.md` の「絵の逆引き」と `docs/shader-doc.md` も同じ入口。

**まず画風を決める。** どんな絵にするかはゲームごとに毎回決め直す物で、既定は無い
（テンプレの見た目・他のゲームの見た目をそのまま持ってこない）。決めたら
`AGENTS.local.md` に 2〜3 行で書く — 何を見て育った絵か・色は何色でいくか・
何をしないか。以下の下限は**その画風を実現する手数を尽くしたか**を測るだけで、
どんな絵にするかには口を出さない。

満たすべきは次の 4 つの**性質**。実現の手は何でもよく、下に挙げる部品はあくまで例。

- **面に階調か質感があること**。`Render.box` を並べただけの画面は未完成 — 単色のベタは
  「ここは平らであるべき」と決めた後の選択であって、既定ではない。
  （手の例: `ShaderDoc` の面 / `Render.vgrad`・`gradPolygon` / `Material` の粒・きらめき /
  `Render.striped`・`checker` / ドット絵のディザ。**1px の色帯を積む近似だけは禁止** —
  焼き時間に直撃するし、上の部品で正しく描ける。使える部品は engine の版で決まるので
  visual-dict の **[新]** 印を見る）
- **主役と背景が分離して読めること**。主役の輪郭が背景に溶けていない。
  （手の例: `PxShade.polishDoc` のふち光・接地影 / 明度差 / 縁取り / `Render.glowAt` /
  背景側をぼかす・沈める。**明度差だけで足りるならそれでよい**）
- **層が分かれていること**（少なくとも 奥・主役・手前）。奥行きの表現が要らないゲームでも、
  情報の優先順位は絵に出す。
- **時間が流れていること**。完全に止まった画面を出さない。
  （手の例: `Fx`・`FxDoc` の粒 / `Sway` の揺れ / 明滅 / 色の巡り / 待ち姿のコマ替え。
  静けさが画風なら、揺れを極小にするのは正解 — ゼロにしないだけ）
  動く値は `EcsTween.Easing` か `Curve` を通す（値を飛ばさない）。

**画風は違っていい・違うほうがよい。** 暗い背景に光る物、明るい紙のような淡い絵、
白地に太い線、色数を絞ったドット絵、単色 2 色だけ — どれも上の 4 つを満たせる。
「暗背景 + 加算グロー + 粒 + 覆い」は visual-dict に載っている**一例**であって、
毎回それを出すのは手抜きと同じ（同じ顔のゲームが並ぶ）。

満たせない事情があるなら **`AGENTS.local.md` に理由を書いて例外にする**。黙って落とさない。
