# 設計: 絵の下限の増強 + UI 文字はみ出しの根絶(改訂 2)

日付: 2026-08-11 / 対象リポ: flix_game_engine / 状態: レビュー 1 回目(68 点)の指摘を反映

## 背景(観測された問題)

1. **造形の穴**: プローブ作り直し(probe_bonfire3)で「テントの入り口が変」。現行の
   絵の下限 4 性質(面の階調・主役の分離・層・時間)は**形そのものが物として読めるか**を
   見ておらず、造形の破綻がスキップされる。RawDraw 隔離時の引き継ぎにも「残=造形の下限」。
2. **UI 文字はみ出し**: AI に UI を描かせると文字が枠からはみ出す事故が頻発。
   現状把握(レビューで現物確認済み):
   - 折り返しの実装は**既に 2 つある**。`TextLayout.layoutPositions` は wrapWidth 引数を
     持つが `Text.toDrawables` が 0.0 を渡していて**死んでいる**。`RichText.wrapLinesBy`
     は UiDialog 本文で**本番稼働中**(maxWidth・文字境界折り)
   - はみ出しの主因は **UiStore → UiExtract(TextComp)経路の実行時文字**
     (`UiSlots.fill` / `UiMenu` の setText で流し込まれる AI 生成の長文言)。
     ここに折り返しの引数が無い
   - 静的な ui.json に入っているのはプレースホルダなので、静的検査だけでは主因を掴めない
3. **文章の劣化**: visual-dict SKILL.md のバージョン注記が 0.14.0 で停止(0.19 Pass/FBO・
   0.20 RawDraw の断りが無い)。「辞書の穴」に解決済み項目(lightAt/darkAt)が残存。
   drawing-floor の「手の例」表に新語彙(lightAt/darkAt/Pass/Curve)が無い。

方針: **真因は文章でなく配線**(矩形だけ問題の実証済み教訓)。文章で頼むより機械が止める。
ただし機械で測れない物(実行時文字の実寸)は**部品側で物理的にはみ出せなくする**。

---

## A. 絵を描くことにやれること

### A1. 造形の下限(5 つ目の性質) — 本丸

**docs/drawing-floor.md に 5 つ目の性質「形が物として読める」を追加する。**

| 満たす性質 | 中身 |
|---|---|
| 形が物として読める | シルエットだけで何か分かる / 部品同士の接続が破綻していない(入り口・持ち手・関節) / 接地している(浮いていない) / 比率が対象らしい |

チェックリスト(visual-dict SKILL.md)にも 1 行足す:
`- [ ] 形が物として読める(シルエット・接続・接地・比率): ____`

**機械の補助 = シルエット焼き**: Bakery に `--silhouette` 変形を足す
(**engine_tools 拡張 → 本設計がその相談**)。

- 対象アイテムを単色(黒)+それ以外を背景白で焼く
- **対象の絞り口を 1 つ持つ**(z-index の範囲 or 名前接頭辞)。全アイテム黒だと画面が 1 つの塊に
  融けて造形が見えないため、既定は「主役の z-index の範囲だけ」。絞り口なしの全黒も選べるが、
  用途は画面全体の重心確認に限ると docs に明記
- critique-bake の手順に「造形が怪しい絵はシルエット焼きで確かめる」を追記

判断軸: 形の良し悪しの判定は人の目視のまま(「良し悪しを決めるのは人」を維持)。
機械は「見やすい材料を出す」までしかやらない。

### A2. バージョン注記の更新(小・機械的)

visual-dict SKILL.md「engine のバージョンと、黙って既定へ落ちる罠」に追記:
- 0.19.0 から: Pass(レンダーターゲット=別の紙)・bakeGifWithPasses・Fx 3 語彙
- 0.20.0 から: 図形プリミティブは `RawDraw.*`(旧 `Render.box` 系は存在しない)

### A3. 「辞書の穴」の掃除(小・機械的)

穴 1 番(glowAt の減衰カーブ)は lightAt/darkAt 実装で半分解決済み。
解決済み部分を消し、残る未解決だけに絞る。

### A4. drawing-floor「手の例」表の追随(小)

- 「面に階調か質感」「主役の分離」の行に `Render.lightAt / darkAt` を追記
- 「層が分かれている」の行に Pass(光マップを別の紙に集めて Multiply)を追記
- 「時間が流れている」の行に `Curve`(sine/tri/arch01/pieces/dampedSpring)を追記

### A5. ループ GIF の継ぎ目検査(bin/lint-loop.py 新設)

probe_bonfire3 が手作業でやった検査を常設化する:
**最終コマ→0 コマの差分画素率が、通常コマ間の差分画素率から外れていないか。**

- 入力: bake 済みコマ PNG(`out/frames/<name>/`。Bakery.bakeGif の出力形と一致)
- 判定: 継ぎ目差分率 > 通常コマ間差分率の最大値 × 1.5 で警告。
  **ただし絶対下限を併設**: 継ぎ目差分率 0.5% 未満は常に合格
  (静けさが画風のループでは通常コマ間差分が ≈0 になり、相対閾値だけだと誤爆するため)
- 純 Python(PNG 画素比較のみ)。エンジン変更なし
- 配線: `make lint-loop` 新設 + make help。保存時フックには乗せない(bake 済みコマが
  前提のため)。bake-loop / critique-bake の手順に組み込む

## B. 文字がはみ出さないようにやれること

設計の背骨(レビュー反映): **本命は B3(部品側の折り返し = 実行時文字も物理的に
はみ出せない)**。機械検査(B2)は「折り返し宣言の漏れ」を見る静的 lint に格下げし、
実寸を測る検査はしない(実行時文字は静的に測れないため)。

### B1. 辞書に採寸の作法を足す(即日)

visual-dict reference.md の UI/文字の節に追記:
- 「文字を枠に入れるときは `Text.measure` で採寸してから枠を決める」
- 「枠が先に固定なら、折り返す(wrap)・fontSize を落とす・文言を縮める、のどれかを
  明示的に選ぶ」
- 「world-entity UI の採寸口は `UiExtract.measureTexts`、UiDialog 本文の折りは
  `RichText.wrapLinesBy`(maxWidth)が既に本番稼働」

### B2. 折り返し宣言漏れの静的 lint(bin/lint-ui-overflow.py・純 Python)

B3 で ui.json の text ウィジェットに wrap 宣言を書けるのを前提に、
**「固定サイズのパネル内にある text ウィジェットが wrap も fit も宣言していない」**
を検出する構造検査。フォントメトリクスは読まない(実寸を測る検査ではない)ので
純 Python で書け、JVM 不要。

- 検出: 親が固定寸(auto-size でない)の text ノードで wrap/fit 宣言なし → 警告
- auto-size ノード(親が文字の実寸から内在サイズを取る)は構造上はみ出せないので対象外
- RichText 経路(UiDialog 本文)は既に maxWidth 必須なので対象外
- 逃がし: 意図的な 1 行固定は `"lint-ui": "対象外 — スコア表示は桁固定"` の理由付き
  宣言で除外(lint-sprite と同じ流儀。黙って除外はしない)
- 配線: `make lint-ui` 新設 + **pre-commit ゲート**(発火は ui.json の変更があった時のみ。
  純 Python なのでゲートの速度感を壊さない)+ 保存時フック(同上)
- 限界の明記: コードから直組みした文字(ui.json を経由しない Text 直呼び)は見えない。
  これは B1 の作法と lint-view(View の目視系)でカバーし、lint の出力にも明記する

### B3. 折り返しの再配線と宣言口(本命・engine / engine_world 拡張 → 本設計がその相談)

**新設ではなく既存 2 実装の再配線。** 折りの規則は既存の本番稼働品
(RichText.wrapLinesBy = 文字境界折り)に**統一**する。空白優先折りや禁則は v1 では
やらない(やる時は Text / RichText 両方同時に)。

経路別に 3 つ:

1. **素の Text(engine)**: `Text` レコードに `wrapWidth: Option[Float64]` を足し、
   `toDrawables` が 0.0 固定で渡している既存の `layoutPositions` wrapWidth 引数に
   これを配線する(死んでいる配線を生かすだけ)。`measure` も wrap 適用後の寸法を
   返すようにする(Layout の自然サイズ問い合わせと折り後の実寸が一致する)
2. **TextComp + ui.json 方言(engine_world)**: text ウィジェットに `wrap`(パネル内寸
   基準の折り)と `fit`(折り後に縦が超えたら fontSize を段階的に縮小、下限で打ち切り)
   の宣言属性を足し、`UiExtract.extract` が TextComp → Text の wrapWidth へ写す。
   **scene.json ファースト規約に従い、Studio のフォームで編集できる形**
   (スキーマ方言への追加を含む)
3. **RichText(UiDialog 本文)**: 既存 maxWidth のまま変更なし

**既定は off(宣言した物だけ折れる)**。理由: 既定 on は挙動変更で、templates の
スナップショットの作り直しと外部リポ全部の見た目変化を伴う。off なら 0.21.0 は完全後方互換で、
新規・修正分は B2 の lint が宣言を強制するので、前向きには塞がる。
ellipsis(…)は v1 ではやらない(切り捨て事故ははみ出しと同型で、既定にすると気づけない)。

完了条件:
- templates のうち UI 文字を持つ物 1 つに wrap 宣言を実際に入れ、bake で折れを確認
- 0.21.0 リリースノートに「新宣言 wrap/fit(既定 off・後方互換)」を記載
- スナップショットの作り直しは不要(既定 off のため)。宣言を入れた template だけ更新し直す

## 実装時の決め(レビュー 2 回目・86 点で挙がった残項目)

1. **B2 が ui.json をどこまで読むか**: 方言の templates/use/instance 合成を Python 側で
   追うか、instance ノードは対象外と明記するか、実装前に決める(UiDoc が唯一のパーサ)
2. **wrap 宣言の値の形**: 数値(px)か `"auto"`(自 rect 幅)か。`"auto"` が素直
3. **fit の縮小刻みと下限 fontSize**: 既定値はスキーマに、宣言側で上書き可
4. **B3 の Studio 作業(別リポ)が 2 日超過の最有力箇所**: 超えそうなら
   「Studio フォームだけ後続に切る」を逃げ道にする
5. **`wrapWidth = None` なら measure は現行どおり**を必ず保つ(後方互換の要)

## やらないこと

- 造形の機械採点(形の良し悪しは人の目視のまま)
- 実寸を測る静的はみ出し検査(実行時文字は静的に測れない。実寸の防御は B3 の部品側)
- ellipsis・空白優先折り・禁則処理(需要が出てから。やる時は Text/RichText 同時)
- wrap の既定 on(スナップショットの作り直しと外部リポ波及を伴うため。宣言 + lint 強制で前向きに塞ぐ)
- 保存時フック・pre-commit への JVM 起動物の追加(B2 は純 Python に設計し直した)
- Python でのフォントメトリクス二重実装
